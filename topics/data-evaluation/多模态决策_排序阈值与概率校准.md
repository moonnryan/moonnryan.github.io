# 多模态决策评测中的排序、阈值与概率校准

在一轮多模态二分类测试中，两个候选的默认准确率分别为 0.802 和 0.801，看起来几乎相同。另一个候选默认只有 0.791，但对同一批预测重新选择阈值后，准确率达到 0.863。

这些数字分别回答了不同问题：默认判定是否合适、正负样本能否分开、分数能否当作概率使用。将它们压成一个排名，会把运行点选择与模型能力混在一起。更有价值的分析，是先分清分数、阈值和最终决策之间的关系，再判断哪些差异能够支持实际选型。

# 一、先区分硬判定与连续分数

本轮主集包含 1000 个样本，正负各半，混合单帧与多帧输入。以下保留部分候选的汇总数字，模型名称和任务类别均作匿名处理；这些结果来自本地测试，不是公共基准成绩。

生成式参考输出离散的正负判断，决策候选额外提供连续正类分数。后者可以按 $\hat y=\mathbf{1}[s\ge t]$ 转成判定，前者在此次输出协议下没有可供扫描的连续分数。因此，生成式参考的准确率应称为原输出判定准确率，不能统一标成 `Acc@0.5`。

| 候选 | 原输出或默认准确率 | AUROC | 原记录 ECE | 同集扫描最高准确率及阈值 |
| --- | ---: | ---: | ---: | --- |
| 生成式参考 | 0.802 | — | — | — |
| 决策 A | 0.801 | 0.904 | 0.068 | 0.830，阈值 0.41 |
| 决策 B | 0.791 | 0.944 | 0.179 | 0.863，阈值 0.15 |
| 决策 C | 0.781 | 0.879 | 0.091 | 0.805，阈值 0.81 |
| 决策 D | 0.468 | 0.461 | 0.108 | 0.505，阈值 0.77 |

决策候选的默认阈值为 0.5；ECE 使用原记录的 15-bin 口径。同集扫描是在上述样本上选阈值并报告最高准确率，包含选择偏差，不能当作独立测试成绩。

生成式参考与决策 A 相差 0.001，在 1000 个样本上只对应一个判断的净差异。它们又共享同一批输入，需要查看逐样本的对错配对和不确定性，不能仅凭这个差值判断稳定胜负。生成式参考没有概率指标，是本次接口和记录的限制，不代表这类模型原则上无法产生其他形式的分数。

结构合法也不意味着判断正确。输出协议与解析问题可参见[Qwen 小模型的结构化输出与任务评测](../models-training/Qwen_结构化输出训练.md)。这里进一步讨论连续分数进入决策之后的含义。

# 二、默认准确率与排序能力可以给出不同结论

决策 B 在默认阈值下，精确率为 0.980，召回率只有 0.594。它很少把负例判成正例，同时漏掉了不少正例。相较于这批样本上最大化准确率的运行点，0.5 的判定较保守。

它的 AUROC 为 0.944，说明在该集合上整体排序较好。降低阈值到 0.15 后，准确率从 0.791 提高到 0.863，变化来自更多样本跨过判定线；模型权重、输入证据及原始分数都没有改变。

决策 C 的方向相反：默认精确率为 0.723，召回率达到 0.910；提高阈值才使准确率有所改善。这说明不同候选的分数分布和默认运行点并不相同，不能把从一个模型选出的数值阈值直接搬给另一个模型。

AUROC 也不能替代目标运行点的检查。它汇总了一段阈值变化下的排序表现，但系统可能只关心很低误报率时还能保留多少召回。一个全局 AUROC 更高的候选，未必在那个局部区间也更好。若应用有明确的误报预算，应报告该预算下的召回，而不是只比较整条曲线的面积。

对于决策 D，同集扫描最高准确率也只有约 0.505，AUROC 为 0.461。这些结果暂时没有显示出足够的正负分离能力。阈值扫描能改变正例数量，却无法凭空创造有用的排序。是否存在标签方向或适配问题，还需要另外核查，不能仅凭低于 0.5 的 AUROC 就自动翻转分数并宣布可用。

# 三、选阈值不会直接修复概率

设模型提供分数 $s(x)$，选阈值只改变最终判定：

$$
\hat y_t(x)=\mathbf{1}[s(x)\ge t]
$$

概率校准则是在已有分数上拟合映射 $p(x)=g(s(x))$，使给出相近概率的样本，其实际正例比例与预测尽量一致。Platt scaling、温度缩放和 isotonic regression 属于这一层的处理。Guo 等人的校准研究强调，分类正确率与置信度可靠性是不同属性；其温度缩放结果也不能直接当作任意多模态任务上的效果保证。

具体方法还取决于接口能提供原始 logit、连续分数，还是只有最终概率。不能在缺少对应输入的情况下，假定论文中的后处理可以原样接入；拟合后的映射也需要在未参与拟合的数据上检查。

因此，将决策 B 的阈值从 0.5 改为 0.15，虽然提高了这批样本上的准确率，却没有使原分数自动变成可靠概率。原始排序没有改变，分数对应的实际发生频率也没有因为判定线移动而改变。

这一区分会直接影响系统使用方式。如果分数只用于二分类门控，合适的运行点可能已经有价值；若还要用于风险估计、跨模型比较或后续概率计算，就需要另外验证概率含义。接口把一个数值命名为 probability，不足以完成这项验证。

原记录中的 ECE 较低，也不能单独证明模型有用。决策 D 的 ECE 为 0.108，低于决策 B 的 0.179，但判定和排序明显更弱。在正负各半的数据上，一个始终输出 0.5 的模型可以在总体可靠性上看起来很好，却没有区分任何样本。

Brier score 同样需要结合排序理解。其二分类形式为：

$$
\operatorname{Brier}=\frac1N\sum_{i=1}^{N}(p_i-y_i)^2
$$

它同时反映可靠性、分辨能力与数据本身的不确定性。更低的 Brier 不必然意味着校准单项更好。ECE 还受分箱规则、样本量和具体定义影响；比较前应固定统计口径，并查看可靠性图与各箱样本数。仅有一个汇总数字，不足以判断所有分数区间都可靠。

# 四、验证的是选择流程，而不只是一个阈值

同一集合上扫描大量阈值，再报告最高值，相当于让评测标签参与了决策规则的选择。扫描出的高点具有探索价值，但其表现通常比未来数据更乐观。scikit-learn 的阈值调优文档也将统计分数与决策规则分开，并强调用交叉验证或独立数据控制选择过程。

对已经固定的模型，阈值交叉验证应在每个训练折内选阈值，再在未参与选择的验证折上评分。它并不需要重新训练模型；但概率映射如果也需要拟合，就必须在相应训练部分完成，不能先用全体标签校准，再只对阈值做交叉验证。

原记录提供了五折汇总，但单凭这份报告不能确认折分是否按关联样本分组，也不能确认选择过程的全部实现，因此这里不将其列为独立验收成绩。正式检验时，更应保留完整流程：冻结候选与提示词，在校准部分确定概率映射和阈值，最后在独立测试部分检查。

如果还利用这些折的结果反复选择模型、语言版本或其他配置，选择偏差会继续积累。即使某个阈值本身是折外评估的，最终挑出的“最好方案”仍值得再经过一份未参与选择的数据检验。

多帧任务还需要处理样本相关性。图像哈希没有重复，只能排除完全相同的图像文件，不能排除同一事件的相邻帧、不同裁剪或重复来源。存在这类关系时，应按事件或来源组划分，使同一组不同时出现在选择端和评估端。分组切分应尽量保留类别比例，但这不保证每个任务在每一折都有足够样本。

置信区间也应尊重这种相关性。例如比较两个模型，可以按组重采样，并在同一次重采样中计算双方差值。把同一事件的多张图当作完全独立样本，容易高估证据量。本轮尚未提供这类区间，表中的小差异应保留为观察。

# 五、全局表现不能替代分任务和目标分布

这轮测试中，有些任务的排序已经较好，但默认召回偏低；另一些任务即使调整阈值，准确率仍然有限。前者更值得检查运行点与概率映射，后者还需要核查输入是否提供了足够证据、标签定义是否一致，以及模型是否真正学会了区分条件。

多个模型在同一任务上共同受阻，是值得回看任务定义的信号，但不能直接认定标注错误。例如，一个判断若需要持续时间、画面外条件或历史状态，单张图像可能无法决定答案；多帧输入也只有在采样覆盖必要信息时才有帮助。关于采样改变输入证据的问题，见[视频转码、抽帧与时间定位的一致性](视频_采样与时间定位.md)。

分任务调阈值同样需要样本支持。任务越多，可选阈值越多，在小集合上越容易追随噪声。可以先看全局阈值下各任务的误报、漏报和分数分布，再决定是否确有必要分别设置，并在独立数据上验证这种复杂度是否值得。

本轮正负各半，也不能代表线上正例比例。即使召回率和误报率保持不变，精确率仍会随正例比例变化：

$$
\operatorname{Precision}=\frac{\pi\,\operatorname{TPR}}
{\pi\,\operatorname{TPR}+(1-\pi)\,\operatorname{FPR}}
$$

这里 $\pi$ 是目标分布的正例比例。作为计算示例，若正例占 1%、召回率为 90%、误报率为 5%，精确率只有约 15.4%。这个例子假设条件错误率保持不变，用来说明平衡集合上的高精确率为何不能直接搬到低发生率环境。

阈值还取决于误报和漏报的代价。若 $p$ 是目标分布下的可靠后验概率，误报代价为 $C_{FP}$、漏报代价为 $C_{FN}$，且正确判定代价为零，则最小化这两项期望代价的阈值为：

$$
t=\frac{C_{FP}}{C_{FP}+C_{FN}}
$$

0.5 对应其中等代价的情形。对未校准分数，不能把这个公式直接当作数值阈值生成器；应先明确优化目标，再用独立数据选择运行点。

# 六、延迟属于服务链路的结果

原始记录还显示，不同候选的端到端 P50 从约 60 ms 到约 1 s 不等。但输入像素上限、推理引擎和输出协议没有完全一致：有的模型生成判断及说明，有的通过决策接口返回分数。因此，这些数字描述的是所测服务配置，不能全部解释成模型结构的加速收益。

即使所有候选都接收同一批样本，视觉编码实际处理的像素和 token 也可能不同。更低的图像上限可以减少计算，同时可能丢失细节。模型、输入预算与服务实现需要共同纳入成本结论。

单并发 QPS 也不等于 P50 延迟的倒数。总体吞吐更接近由总请求数除以总耗时计算，受慢请求、处理间隙等影响；P50 只描述中位请求。应同时保留平均值、P95、请求边界及重试策略，再判断是否满足目标负载。

原记录有少量生成截断后提高输出上限补跑的情况。最终解析率可以按补跑后的结果计算，但不能同时把它视作统一输出预算下的一次成功率。服务验收还应分别统计首次解析成功率、重试次数和包含重试的延迟，避免格式修复成本从结果中消失。

# 七、提示词变化也会改变运行点

同一权重的两个语言版本中，默认准确率从 0.774 变为 0.791，而 AUROC 从 0.942 变为 0.944。默认判定变化比总体排序变化明显，这提示应同时观察分数分布与排序，不能只用准确率差异解释成视觉理解整体增强。

语言版本不是独立模型，也不构成独立重复实验。翻译可能改变措辞、指令强度和条件解释，无法仅凭这些汇总指标确认变化来自训练语言、概率尺度或某种特定机制。实际提示词应与阈值一起冻结；换提示词后，原阈值也需要重新核对。

这轮结果支持的判断是：默认运行点、排序能力、概率可靠性与服务成本应分别评估，再按实际目标组合。最高的同集扫描准确率提供了继续验证的方向，独立数据上的决策表现才决定这个方向是否成立。
