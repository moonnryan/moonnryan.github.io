# 多模态决策模型评测：任务、阈值与概率校准

一轮多模态二分类测试中，两个候选的默认准确率分别为 0.802 和 0.801。另一个候选默认只有 0.791，但对同一批预测重新选择阈值后达到 0.863。排名随判定规则改变，却不意味着模型读取了更多证据，或者概率变得更可靠。

评测需要解释这类差异来自哪里：输入是否足以支持判断，模型能否分开正负样本，分数怎样转成决策，以及整个服务实际交付了多少有效结果。

# 一、模型接口与任务证据

多模态决策模型接收状态、问题和允许的选项，返回类型化答案及分数。生成式 VLM 通常逐步输出文本再解析字段，专用决策路径则可以直接对选项评分。两者的输出机制不同，但都要完成证据理解与条件判断。

截至 2026 年 11 月，本轮涉及的几类公开模型各有侧重：

| 公开模型 | 官方资料描述的决策路径 |
| --- | --- |
| [AutoTrust JEV-9B](https://huggingface.co/autotrust/JEV-9B) | Qwen3.5 基座加决策 adapter 与 head，保留生成路径；图像通过 VL 服务接入，与 TypeSafe Jev 是不同产品 |
| [OneJev 1.6](https://github.com/OmniJev/OneJev) | 基于 Qwen 的多模态 System One 模型，一次前向回答类型化问题 |
| [Cloudflare Clef-Flash](https://huggingface.co/Cloudflare/clef-flash) | 9B 多模态骨干加联合 schema head，联合处理问题与选项，输出各问题的选项 logit |
| [Liquid AI d1-2B](https://huggingface.co/LiquidAI/d1-2B) / [d1-3B](https://huggingface.co/LiquidAI/d1-3B) | 分别基于 LFM3-VL / LFM2.5-VL，直接返回类型化答案；Omni 分支新增的模态需另测 |

“一次前向”并非统一的成本单位。视觉编码、输入长度和问题数量仍影响计算；有些服务用受限选项 token 读取分数，也不能只按输出 token 数推断开销。官方描述的校准能力同样要在目标分布上重新检查。

本轮主集包含 1000 个样本，正负各半；单帧 431 个，多帧 569 个，每个样本最多 6 帧。数据来源、场所和内部规则省略，任务按所需证据归为以下类型。表中列的是关注点，本轮没有逐项统计这些错误。

| 任务类型 | 需要区分的证据 |
| --- | --- |
| 物体与区域状态 | 堆放、容器状态与区域条件；物体存在不等于状态已经超限 |
| 密度与通行状态 | 数量、透视、区域面积与可通行空间，避免只按目标数量判断 |
| 人体动作与交互 | 姿态变化、跌倒或接触冲突的过程，避免把单帧姿态直接当作事件 |
| 细节与异常外观 | 手口附近的小物体、局部行为、烟火样外观；关注细节损失与相似背景 |
| 规则约束的状态 | 停留、区域限制与持续状态；确认区域、时长和规则前提是否已提供 |

状态类任务可能由单帧支持，动作类任务往往需要过程，规则类任务还可能依赖画面之外的信息。多帧也不自动提供时长：缺少采样间隔时，不能按帧数推断持续时间；两帧相似也不证明中间状态没有变化。采样与时间信息的处理见[视频转码、抽帧与时间定位的一致性](视频_采样与时间定位.md)。

这种证据差异决定了分任务分析的意义。多个模型共同受阻时，先核对输入与判断条件是否匹配，再检查模型能力。单纯调整阈值无法补足缺失的时序、局部细节或外部规则。

# 二、排序、运行点与概率是三件事

以下是部分匿名候选的本地结果，不对应上表公开型号。生成式参考仅输出硬判定，决策候选的默认阈值为 0.5；因此不能把所有行统一称为 `Acc@0.5`。

| 候选 | 原输出或默认准确率 | AUROC | ECE | 同集扫描最高准确率及阈值 |
| --- | ---: | ---: | ---: | --- |
| 生成式参考 | 0.802 | — | — | — |
| 决策 A | 0.801 | 0.904 | 0.068 | 0.830，阈值 0.41 |
| 决策 B | 0.791 | 0.944 | 0.179 | 0.863，阈值 0.15 |
| 决策 C | 0.781 | 0.879 | 0.091 | 0.805，阈值 0.81 |
| 决策 D | 0.468 | 0.461 | 0.108 | 0.505，阈值 0.77 |

ECE 沿用原记录的 15-bin 口径。同集扫描同时使用这批标签选择和评价阈值，包含选择偏差，不能当作独立测试成绩。

决策 B 默认精确率为 0.980、召回率为 0.594，表现为少误报、多漏报。较高的 AUROC 表明这批数据上的整体排序较好，降低阈值后更多正例跨过判定线，准确率随之提高。决策 C 默认精确率为 0.723、召回率为 0.910，提高阈值才改善准确率。它们需要不同运行点，数值阈值不能直接跨模型搬用。

但 AUROC 汇总整段阈值范围，未必反映很低误报率下的表现。如果系统只允许极少量误报，应比较该预算下的召回，不能用全局面积代替局部运行点。决策 D 连同集阈值扫描也没有显示出足够的区分能力，继续挪动判定线并不会创造新的证据或排序。

选阈值只改变 $\hat y=\mathbf{1}[s\ge t]$；概率校准则拟合 $p=g(s)$，使相近预测概率对应的实际正例比例尽量一致。将 B 的阈值改成 0.15，不会直接改善原分数的概率可靠性。Platt scaling、温度缩放与 isotonic regression 才属于概率映射层的处理，具体选择还取决于接口能提供分数、logit 还是最终概率。

反过来，低校准误差也不足以证明模型有用。D 的 ECE 低于 B，但排序与判定更弱；在正负各半的集合上，始终输出 0.5 可以在总体可靠性上看起来很好，却没有区分任何样本。Brier score 还同时包含可靠性、分辨能力和数据不确定性的影响，不能将它单独解释成校准质量。结合可靠性图、分箱样本数与任务排序，才能判断分数适合门控、风险估计还是后续概率计算。

# 三、选择流程与目标分布决定结果能否迁移

阈值是待选择的决策参数。对固定模型做阈值交叉验证，应在每个训练折内选阈值，再在未参与选择的验证折上评分；若同时拟合概率映射，也必须在相应训练部分完成。用全体标签先校准，再只对阈值交叉验证，会让验证部分提前参与拟合。

原记录给出了五折汇总，但没有提供足以核对分组和选择实现的完整信息，这里不列为独立验收成绩。如果又根据这些结果反复挑选模型、语言或配置，即使阈值已做折外评分，最终选出的方案仍会积累选择偏差，需要保留未参与选择的数据作最后检验。

语言影响也应放进这个流程。一次同权重对照中，默认准确率从 0.774 变为 0.791，而 AUROC 仅从 0.942 变为 0.944；这提示应同时检查分数尺度与排序，不能把默认准确率变化全部解释成视觉能力增强。提示词应与模型、阈值一起冻结，翻译版本不构成独立模型或独立重复。

多帧任务的切分单位也很重要。图像哈希去重排除了相同文件，却排除不了同一事件的相邻帧和不同裁剪。有关联的样本应按事件或来源组切分；比较模型差异时，也可按组进行配对重采样。生成式参考与 A 的准确率净差只对应 1000 个样本中的一个判断，缺少逐样本配对与区间时，不足以判断稳定胜负。

此外，平衡评测集不能代表线上正例比例。若召回率和误报率保持不变，精确率随目标正例比例 $\pi$ 变化：

$$
\operatorname{Precision}=\frac{\pi\,\operatorname{TPR}}
{\pi\,\operatorname{TPR}+(1-\pi)\,\operatorname{FPR}}
$$

例如正例占 1%、召回率 90%、误报率 5% 时，精确率只有约 15.4%。这是保持条件错误率不变的计算示例，说明平衡集合上的表现为何不能直接搬到低发生率环境。

若 $p$ 是目标分布下可靠的后验概率，误报、漏报代价分别为 $C_{FP}$、$C_{FN}$，正确判定代价为零，则最小化期望代价的阈值为：

$$
t=\frac{C_{FP}}{C_{FP}+C_{FN}}
$$

0.5 对应等代价的情形。对未校准分数，应通过独立数据选择满足实际目标的运行点。分任务阈值可以增加灵活性，也会增加待选择参数，样本少时更容易追随噪声；应先确认各任务确实需要不同决策，再验证额外复杂度的收益。

# 四、把输出失败与重试计入交付结果

生成式参考与直接评分接口的比较，还要统一有效输出的定义。有效 JSON 不一定符合字段约定，字段合法也不保证判断正确。接收端应分别检查请求完整性、严格解析与字段类型；超时、截断或解析失败保留为失败状态，不能自动转换成任务负例。

设全部请求数为 $N$，有效输出数为 $N_{\mathrm{valid}}$，其中判断正确的数量为 $N_{\mathrm{correct}}$，则：

$$
\mathrm{Acc}_{\mathrm{e2e}}
=\frac{N_{\mathrm{correct}}}{N}
=\frac{N_{\mathrm{valid}}}{N}\cdot
\frac{N_{\mathrm{correct}}}{N_{\mathrm{valid}}}
$$

这里端到端指标要求输出有效且判断正确，解释质量另算；没有有效输出时，条件准确率不可计算。只在可解析样本上报告准确率，会隐藏困难样本被格式失败过滤掉的问题。至少应同时报告有效覆盖率、有效输出上的判断指标和端到端正确率。

本轮有少量生成截断后提高输出预算补跑的情况。因此，最终解析率不能等同于统一预算下的一次成功率；首轮结果、重试结果及包含重试的时延需要分开记录。格式修复带来的成本，也属于模型交付路径的一部分。

原记录的端到端 P50 从约 60 ms 到约 1 s 不等，但视觉输入上限、引擎和输出协议没有完全统一。这是服务配置的比较，差距不能全部归因于模型结构。减少像素可能加快编码，也可能损失细小目标；生成说明与返回分数的输出成本也不同。

吞吐应按总请求数与总耗时计算，P50、P95 分别观察典型请求与尾部请求，不能用 P50 的倒数代替总体 QPS。冻结输入预算、输出协议与重试策略之后，再结合准确率、运行点和概率可靠性选择候选，结论才对应一条可以交付的实际链路。
